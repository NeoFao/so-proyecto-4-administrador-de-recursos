# INDICADOR DE EVOLUCIÓN ENTRE PROYECTOS
## TIIT2007 – Sistemas Operativos | Universidad Invenio

---

## 1. Propósito

Las rúbricas existentes (Rúbrica 1 Analítica, Rúbrica 2 ISO/IEC 25010) evalúan cada proyecto **de forma aislada**. Este instrumento añade una capa longitudinal: mide si el estudiante **progresa** a lo largo de los 4 proyectos en dimensiones que deberían mejorar con la práctica acumulada — independientemente de que cada proyecto trate un mecanismo distinto de SO.

Este indicador **no añade peso adicional a la nota final** (el 100% ya está distribuido); es un instrumento de seguimiento formativo y de mejora continua, y un insumo valioso para la Defensa Técnica y el Portafolio.

---

## 2. Dimensiones de Evolución a Rastrear

| Dimensión | Qué mide | Fuente de evidencia |
|---|---|---|
| **Calidad de código** | Modularidad, manejo de errores, legibilidad | Criterio "Calidad del diseño/código" de la Rúbrica 1, en cada proyecto |
| **Profundidad del análisis experimental** | Capacidad de interpretar datos, no solo reportarlos | Sección "Discusión de Resultados" del documento IEEE, evaluada cualitativamente |
| **Autonomía respecto a IA generativa** | Disminución de dependencia / aumento de criterio propio en decisiones de diseño | Observación docente + desempeño en Defensa Técnica respecto a cada proyecto |
| **Calidad de la autoevaluación ISO/IEC 25010** | Justificación cada vez más precisa y menos genérica | Comparación de las 4 autoevaluaciones ISO/IEC 25010 entregadas |
| **Tiempo de entrega relativo al plazo** | Mejora en gestión del tiempo y planificación | Fecha de entrega de cada proyecto vs. fecha límite |

## 3. Instrumento — Ficha de Seguimiento Individual

Se completa progresivamente por el docente (o el propio estudiante como autoevaluación, recomendado para el Portafolio) al cierre de cada proyecto.

| Dimensión | Proyecto 1 (S4) | Proyecto 2 (S6) | Proyecto 3 (S8) | Proyecto 4 (S11) | Tendencia |
|---|---|---|---|---|---|
| Calidad de código (1–4) | | | | | ↑ / → / ↓ |
| Profundidad de análisis (1–4) | | | | | ↑ / → / ↓ |
| Autonomía vs. IA (1–4) | | | | | ↑ / → / ↓ |
| Calidad autoevaluación ISO (1–4) | | | | | ↑ / → / ↓ |

**Escala 1–4:** equivalente a la escala de las rúbricas del curso (Insuficiente–En desarrollo–Competente–Excelente), para mantener consistencia.

---

## 4. Lectura de Tendencias — Guía de Interpretación

| Patrón observado | Interpretación posible | Acción sugerida |
|---|---|---|
| Mejora sostenida (↑) en todas las dimensiones | Aprendizaje genuino y acumulativo | Reconocer explícitamente en retroalimentación; útil como evidencia positiva en Defensa Técnica |
| Estable (→) en nivel alto desde el Proyecto 1 | Buen nivel de entrada; el curso no necesariamente lo desafía progresivamente | Plantear retos adicionales opcionales en Proyecto 4 |
| Estable (→) en nivel bajo | Brechas no resueltas a tiempo (posible vínculo con resultado Amarillo/Rojo del Diagnóstico C++) | Revisar si el refuerzo asignado tras el diagnóstico fue efectivo |
| Caída (↓) entre proyectos consecutivos | Puede indicar sobrecarga académica, problema personal, o tema del proyecto particularmente desafiante | Conversación individual oportuna; no esperar a la Defensa Técnica para detectarlo |
| Autonomía vs. IA decreciente (↓) | Posible aumento de dependencia de IA sin comprensión creciente | Reforzar explícitamente la Política de IA; aumentar preguntas de variación en próxima Defensa Técnica |

---

## 5. Vínculo con Otros Instrumentos del Curso

- **Defensa Técnica Individual:** el docente puede usar la fila "Autonomía vs. IA" para decidir en qué proyecto concentrar las preguntas de variación (ver Banco Histórico de Preguntas de Defensa, documento dedicado).
- **Portafolio Técnico Final:** se recomienda que el estudiante incluya su propia lectura de esta tendencia como parte de la Reflexión Profesional Final (pregunta 5: "¿qué harías diferente...").
- **Estrategia de Mejora Continua:** si una cohorte completa muestra tendencias (↓) generalizadas en una dimensión específica, es señal de que el problema es de diseño del curso, no individual del estudiante.

---

## 6. Aclaración de Alcance

Este instrumento es **formativo y de seguimiento**, no sustituye ni duplica la Rúbrica 1/Rúbrica 2 ya aplicadas a cada proyecto. Su valor está en hacer visible — para el docente, el estudiante y la coordinación académica — una dimensión que de otro modo queda implícita: **¿el estudiante realmente está mejorando a lo largo del curso, o solo está completando tareas independientes entre sí?**
